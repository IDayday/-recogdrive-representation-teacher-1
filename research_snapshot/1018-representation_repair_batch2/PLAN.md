## 1. 研究依据与结论边界

第一批的正式证据入口为[表征与修复报告](../doc/work-output/1016-rl_representation_analysis/representation_observation.html)、[精准修复上限汇总](../1016-rl_representation_analysis/vlm_repair_v1/oracle_policy_groups/20261017T172416/SUMMARY.json)和[最终科学验收](../1016-rl_representation_analysis/provenance/VLM_FINAL_PACKAGE_VERIFICATION.json)。第一批已覆盖动作头、VLM骨干和接口的大范围表征分析及多种修复尝试，目前没有确认可部署方案带来稳定的整体能力净提升。

现有实算候选库中，VLM／接口的特权选择收益高于动作头，因此本批将主要研究投入放在上游；动作头保留有针对性的补充与对照。这里的 Oracle 是在已有候选、已有样本及噪声下利用真实结果选择，并保留 Base 的诊断。它既不是仅知道“会失败”就一定能获得的收益，也不是该位置所有可能干预的理论上限；不同候选库的搜索预算也不完全相同。

需要验证的工作假设：全体失败的统计可能混合了互相冲突的修复需求。统一方向、统一算子或统一力度可能无法兼顾，而部分子群可能存在可重复的局部修复规律。团队“部分难例专门微调仍学不会”的经验支持提出这个问题，尚不能证明其原因一定是梯度或修复方向冲突。

本批分别回答三个问题：**能否形成有效且互补的专家；能否用部署时可得信息选对专家和力度；上述能力能否跨会话、跨噪声泛化。** 不要求专家具有人工可解释的失败名称，也不把成功／失败分类准确率当作修复能力。

## 3. 数据、随机数与评价隔离

### 3.1 数据来源与质量定义

- 主体是 navtrain 的自然 RL 输出及对应表征。第一批 S0 全量覆盖103,288场景，可复用轨迹、评分与合格缓存；实际来源、覆盖和身份先核实。稳定失败与稳定成功都要覆盖，不能只研究少量成功／失败翻转场景。
- 失败为 **PDMS < 70**，高质量成功为 **PDMS > 90**，`70 ≤ PDMS ≤ 90` 为中间质量；使用未舍入评分。无效输出及评分异常独立统计。
- 专家子群的空间估计主要使用失败；系统训练和评估必须同时覆盖高质量成功、中间质量与失败，保留原成功损伤。对无法被旧方法改善的失败继续探索，不提前删除。
- VLM／接口采用路线一：自然输出质量对应的跨场景分布。同观测的上游表征不因动作采样不同而改变，不能伪造 VLM 处同输入的成功／失败参考差分。
- 动作头补充若使用路线二，仍将失败输出与 GT 配对、加噪、完整去噪后重新评分；原 GT 不按90分提前筛除。最终质量标签由新轨迹决定，P0／P1稳定性单独检验，两路线不混用。

### 3.2 划分与选参

优先沿用第一批 navtrain 的会话级探索／留出清单并核实来源，同一场景全部噪声和相关日志成组归属。探索集内部按会话交叉验证；空间拟合、成功参考选择、子群形成、路由学习和阈值校准都遵守折边界。不得先用全体样本形成子群／基，再把交叉验证只用在最后的路由器上。

专家数、初始化、位置、子空间、算子、力度及路由的主要选择在探索交叉验证完成；进入完整留出确认前冻结候选与规则。若根据留出结果继续修改，明确改记为开发反馈，重新安排确认，不能继续称该结果为未参与选参的确认。最终测试在方案锁定后进行，不根据测试结果改变专家或门控。历史报告作为既有证据，不把过去使用过的 navtest 宣称为全新测试集。

失败富集面板可用于探索，但记录抽样及权重；总体性能使用自然分布或完整总体评价，不能直接把富集面板均分当作整体提升。完整保留样本落选、缺失、无法配对和无法修复的分母。

### 3.3 种子与重放

自然采样沿用第一批的 S0 命名和映射：根种子 `20261008`，S0对应 `j=0`，S1／S2等对应后续编号。

```python
seed = int(sha256(f"{token}|20261008|{j}".encode("utf-8")).hexdigest()[:8], 16)
```

实现复用[第一批种子协议说明](../1016-rl_representation_analysis/PLAN.md)，包括随机流初始化与实际噪声控制；S0不是所有场景共用整数0。Base与干预配对相同场景、采样编号和应匹配的随机量；新增模块不能意外消耗并改变动作采样随机流。节点、rank、分片和恢复顺序不能改变种子。

专家／路由初始化、分组初始化、随机空间构造分别使用独立命名的种子表，具体整数在运行前写入协议，不与自然采样编号混淆。正式候选采用多个独立拟合初始化；自然采样开发复核至少3组，最终测试沿用5组 S0–S4。跨噪声诊断使用未参与相应拟合／指派更新的采样编号，报告各组的实际用途，不选择成绩最好的拟合种子代替整体结果。

## 4. 专家如何定义与控制干预

对专家 e，完整配置记为 `E_e = {位置 L_e，token/区域 T_e，空间 B_e，算子 F_e，力度策略 a_e，范数预算 c_e}`。可学习参数与离散候选配置分别保存。若包含多位置，还须记录执行顺序、各位置预算与整体预算。

| 维度 | 探索内容 | 主要约束 |
| :--- | :--- | :--- |
| 在哪修 | 上游各层、投影与接口、全体／局部／语义token；重点候选再比较少量联合位置 | 每层／组件保留探索入口，不只沿用全局最优层；联合位置不从一开始做任意笛卡尔积 |
| 在什么空间修 | 子群自己的成功／失败主空间、残差、成功空间内部差异；行为敏感方向及可学习低秩空间 | 各专家独立拟合；随机同维及受限全维作对照 |
| 怎么修 | 平移、收缩／抑制、正则分布运输、局部条件映射、按最终行为学习的低秩修正 | 不把所有失败都推向同一个成功均值；旧方法仅为初始化及候选来源 |
| 修多少 | 每样本连续力度、精确0、离散力度网格及其局部细化；必要时方向符号另作配置 | 实际修改范数和行为结果共同约束；不能靠名义系数判断强弱 |

先以结构化候选搜索位置和空间，再拟合算子与力度，随后更新分组；后期允许联合优化。不同专家最终可以不同，但不在初始阶段同时无约束放开所有参数，避免无法判断改进来自何处。

记录修改前后张量差、每token及整体相对范数、裁剪比例、实际修改覆盖率，并核验 BF16 量化后的真实编辑。范数小不等于行为安全，仍需完整生成与评分。多位置预算不得通过增加位置数隐性放大。

## 5. 共享成功参考与各子群的独立空间

共享的是**同一位置的成功样本库／分布及可复用统计**，不是要求全部专家共用一个最优基或一个目标均值。不同位置各有自己的成功库；每位专家可选择不同主空间维数和成功参考权重。

设探索训练折中的高质量成功库为 S，失败 i 对专家 e 的软归属为 `q_ie`，则专家的失败统计由加权集合 F_e 估计。比较三种空间构造：

1. **相对成功空间的失败残差。** 从 S 和 F_e 分别求主空间，消除成功主空间解释的部分，再对残差做 SVD，或使用其他等价的差异空间构造。
2. **成功空间内部的差异。** 比较投影均值、协方差、条件关系及占用方式；失败可能来自正常能力的组合／使用不当，只看正交残差可能漏掉这些信号。
3. **从共享库自动匹配成功参考。** 按可观测场景／状态自动重加权成功样本，比较共享全库与局部匹配。不预先手工划分“成功类型”，不以 GT 或测试结果完成部署时的匹配。

三类构造分别比较，不预设其中一种必然更好。成功保持评价始终覆盖全体原成功，不能只保护专家匹配到的少量成功样本。

主空间与残差维数复用第一批的宽候选范围，并按每个子群／训练折的实际秩裁剪：

| 参数 | 候选范围 |
| :---: | :--- |
| `k_s`、`k_f` | 4、8、16、24、32、48、64、96、128、192、256、384、512、768、1024、1536、2048、3072、4096 |
| 残差 `r` | 2、4、8、16、24、32、48、64、96、128、192、256、384、512、768、1024 |
| 中心化 | 未中心化、共同中心化；其余标准化单独记录，不能混为同一配置 |
| 对照 | 等维主空间为主；非等维独立比较；随机同r、全维及成功空间内部差异 |

这是可探索范围，不要求所有 K、全部交替轮次、每个子群都机械重复第一批全笛卡尔积。先在全位置和低／中／高秩范围分层搜索，再对有实际干预收益或互补潜力的区域加密；每层／构造保留代表，不只依据全局质量分类能力淘汰。记录实际覆盖、裁剪与尚未搜索组合，不能宣称穷尽。

保留固定 `k_f,r` 改变 `k_s`、固定 `k_s,r` 改变 `k_f`、固定主空间改变 r 的比较，不同主空间按相同最终r比较。报告数值秩、奇异值退化、加权有效样本量及会话数；有效样本量不是矩阵秩的替代定义。小组不强行拟合高维基，使用正则化、降秩或合并，记录规则。

优先复用逐样本表征和已有统计，重新按组权重计算。**全局充分统计通常不足以恢复任意新分组的统计**；先核查原始缓存的层／token粒度、精度和覆盖，缺少必要信息时只做有目的的补采，使用独立版本，不覆盖原缓存。

## 6. 让失败分组与专家自然形成

没有天然的“类型A”标签，也不先假定按原始表征聚类就能得到可修复类型。分组的最终依据是：**某些样本能否共享一套干预并获得可重复的真实收益。** 原始表征距离、传统失败分项仅作辅助。

### 6.1 多种初始化

并行比较以下起点，均仅在探索训练折构造：

- 成功参考下的残差、成功空间内部差异及其多视角表示。
- 已有及新探索算子的**干预响应**：PDMS变化、碰撞／出界／零分变化、原高质量损伤、力度敏感性和跨噪声稳定性。
- 少量逐场景受限优化得到的有效修正，用作寻找新方向与新子群的线索。

响应向量需考虑分项尺度、缺失和不确定性；没有实算结果不能当作零收益。旧方法都无效的样本进入未解释部分，继续尝试新空间／位置，不能因初始化无信号而永远排除。

### 6.2 交替更新

1. 给失败样本初始化软归属 `q_ie`，允许暂时属于多个修复需求。
2. 按归属权重重估各组 F_e，与共享或匹配成功库比较，独立搜索专家的位置、空间、算子和力度。
3. 实际施加干预，运行后续网络和完整去噪，对真实轨迹重新评分；对重点响应换噪声复核。
4. 根据真实收益、损伤风险和可重复性更新归属；共享专家内部若出现明显冲突，尝试拆分；高度重复且无独立贡献的专家尝试合并。
5. 用探索会话的折外表现判断改动，再进入下一轮。完成专家／分组的初步稳定后训练部署路由，之后可有限交替更新。

这里的归属是训练期利用结果形成的研究变量，不是部署时天然可知的标签。通过多个初始化、会话交叉拟合和独立噪声检查，控制“先按某算子分组，再证明该组适合该算子”的自证偏差。

各 K 都完整比较，不强迫每个专家有相同样本数或正交方向。分裂／合并可复用相邻K的结果，但每个K保留独立初始化，降低路径依赖；报告名义K、有效活跃专家数、覆盖率、独特修复贡献及专家之间的重合。

## 7. 路由、零专家与强度

路由目标优先学习“哪个干预在此条件下有收益／风险，以及应该用多大力度”，而非只学习成功／失败二分类。表征高度重叠并不自动排除条件收益可预测性；反之，专家可修复也不保证路由能预测。

### 7.1 零专家

零专家 `E_0` 是严格恒等：`Δ_0=0`。既可服务原成功，也可服务暂时无法可靠修复的失败。允许零专家权重达到90%乃至100%；不因占比较高而强制转给其他专家。训练探索阶段仍须实际评估部分非零专家，避免初始保守路由导致所有专家都得不到学习信号。

不采用强制均匀分配的负载均衡目标；若使用防坍缩机制，区分训练期探索与部署决策，并核验不会逼迫正常样本接受修改。

### 7.2 三种决策方式

| 方式 | 运行形式 | 必须验证的问题 |
| :--- | :--- | :--- |
| 硬路由＋连续力度 | 选择零专家或一个非零专家，再预测力度；力度也允许精确0 | 错路由损伤、拒绝／保留Base的校准、专家重叠区域 |
| 软干预混合 | 根据权重混合各专家的表征改变量，并对混合结果联合训练／评价 | 混合的实际效果是否抵消、放大或产生新风险，不能按单专家收益线性推算 |
| 独立生成后选择 | Base及各专家分别生成完整轨迹，使用部署可得信息选择一条 | 选轨迹能力与干预能力分开；不能以真实PDMS充当部署打分器 |

软混合满足 `w_0 + Σ_e w_e = 1`，`w_e ≥ 0`。同位置可写作 `h' = h + Σ_e w_e a_e Δ_e(h)`；不能丢弃零专家后将剩余权重重归一化，否则会消除“不修／少修”的意义。权重与力度同时可学时记录实际乘积与编辑范数，不给单独权重强加语义。

不同层、token或维度的专家不能直接相加原始向量。需在各自位置定义干预、明确顺序，在同一次真实前向中联合验证；或采用独立轨迹分支。后一方式选择完整轨迹，不是对轨迹坐标加权平均。高零专家权重也不自动保证安全。

### 7.3 可用信息分层

| 路由信息 | 能回答的问题 | 执行要求 |
| :--- | :--- | :--- |
| 观测、自车状态、VLM／接口表征 | 场景条件下哪种干预的期望收益更高 | 同观测的不同采样通常共享这些信息，不能保证识别某次随机失败 |
| 当前动作生成状态／动作头表征 | 当前采样更适合哪种干预 | 若用来决定更早的VLM干预，需显式增加第二次前向 |
| Base完整轨迹及可计算的轨迹特征 | 先观察Base行为，再选择是否重新生成及如何干预 | 允许两次或多次推理；不含GT、真实环境评分或不可用未来信息 |

训练／开发可用真实评分学习条件收益和风险，评估时实际路由只能接收上述允许信息。特权指派、最优力度和Oracle结果独立标记。

## 8. 方法族与有增量的对照

各专家都可探索以下方法族，不要求所有专家使用相同族。旧全局算子可作为起点，即使旧全局平均不佳，也可能成为子群候选。

| 方法族 | 本批相对第一批的关键变化 |
| :--- | :--- |
| 子群平移、收缩、方向移除／投影、正则运输 | 在该专家负责的失败分布上重新估计方向、基和参数，比较共享及匹配成功参考 |
| 局部／条件化映射 | 同一专家内部按场景连续调整，避免每个组仍只有一个固定方向 |
| 按最终行为训练的低秩修正器 | Base冻结，梯度经过后续网络／去噪链；目标指向轨迹／安全及能力保留，而不只逼近成功hidden |
| 行为敏感方向、token与路径选择 | 比较容易读出质量的方向与真正影响行为的方向，寻找两者兼具的部分，作为专家空间来源 |
| 少量逐场景受限修正 | 发现旧空间／旧算子遗漏的可控方向，为初始化、拆分及“不能修还是不会选”提供诊断 |

PDMS含硬门槛，不能假装全部可微。梯度训练使用明确的轨迹／安全代理或经真实评分验证的修正目标；必要时使用黑盒评分探索。代理改进必须由真实重新评分验证，保留代理改善但PDMS／安全退化的记录。仅换更大MLP、仅做hidden距离拟合，不单独算作本批的主要方法增量。

核心对照包括：精确Identity；已有单一方法；同位置／同维／匹配实际力度的随机干预；固定共享空间与按子群重估空间；共享成功库与自动匹配库；仅调力度与同时改变算子／空间；三种路由；部署路由与特权选择。

不新增K=1训练。可单独评估已经拟合的每位专家或复用第一批单一方法，展示独立能力与组合互补性；记录总参数量、实际调用数及探索预算，明确专家数量和容量变化的归因边界。多候选方式加入匹配候选数／噪声数的Base重采样对照，避免将更多采样机会全部归因于修复。

## 9. 特权上限与修复冲突诊断

上限必须基于**同一面板、相同采样协议下实际生成的完整轨迹**。只在Base失败上运行过的方法，不能默认其在原成功上无损，从而用于评估可部署路由。

| 诊断 | 允许使用的额外信息 | 解释 |
| :--- | :--- | :--- |
| 完美失败触发 | 知道Base是否低于70；算子／策略保持固定 | 仅移除触发错误，修复失败本身仍可能发生 |
| 有益才替换 | 知道Base与一个固定候选的实际收益 | 区分同一算子的潜力与错误修改代价 |
| 专家＋力度Oracle | 在已实算专家／力度与Base中按真实结果选优 | 当前候选库的选择上限，不是部署能力 |
| 场景固定专家 | 一个场景跨采样固定专家，另报是否固定力度 | 区分场景层面的稳定分工与逐次采样特权选择 |
| 逐场景受限优化 | 用真实评分或代理反馈寻找内部扰动 | 诊断位置／空间可控性，不能作为普通推理成绩 |

分开报告强制“只改Base失败”和允许改善其他质量样本的Oracle；安全优先及PDMS优先口径均保留。报告逐输出、逐场景跨噪声、固定专家与可换专家的区别，防止一个最大数字掩盖不稳定。

对怀疑冲突的样本，比对逐场景／相似小组修复、旧共享算子与新分组专家的真实结果。若个别可修而共享干预此消彼长，再检查有效修正的相容性；梯度余弦或向量夹角只作线索，不直接证明功能冲突。若逐场景也难以修复，则保留为可控性不足或搜索未充分的候选解释。

## 10. 筛选、统计与正式结论

候选筛选同时考虑真实净收益、原能力损伤、跨会话／噪声稳定性、专家互补性和相邻参数支持。分布差异、AUROC／AP或能量仅作辅助，不以显著性或分类分离单独决定修复候选。

至少汇报以下指标：

- 全体平均PDMS变化及会话聚类置信区间；失败／中间／原高质量各自贡献。
- 原失败到 `≥70`、到 `>90` 的数量与比例；原高质量到 `≤90`、到 `<70` 的损伤。
- 新增、消除及净碰撞／出界／零分；TTC、总失败、进度等另列，不能只给均分。
- 稳定失败跨噪声修复、复发与原稳定成功损伤；各专家覆盖、实际非零编辑率、独特贡献及重合。
- Oracle与实际路由之间的收益差距、错路由损伤、力度校准、零专家比例及不同信息层级的作用。
- 独立拟合初始化、采样噪声及会话的不确定性；完整搜索范围、不可行／无效／未运行项及选择规则。

**安全优先**沿用用户确认的规则：开发评价中净碰撞、净出界、净零分不增加；TTC和总失败数另列，不自动增加为硬约束。同时报告新增与消除事件，净不增加不等于逐样本无伤害。**PDMS优先**保留最高总体收益候选，完整披露安全代价。若没有满足安全约束的方法，明确报告，不将最保守但仍违约的方法称为达标。

探索搜索的多重比较与最终冻结候选的推断分开：保存完整候选家族；探索阶段可做FDR控制与折外描述，最终确认按冻结比较家族做Holm等校正，并报告会话聚类效应区间。所有自适应筛选在确认前冻结；不以挑出的单个最佳点、单个种子或一个p值宣称稳定提升。具体比较家族及计算实现写入运行协议。

不预设未经确认的固定提分阈值。稳定净收益需要整体效应、跨会话／噪声／拟合重复及安全代价共同支持。只有条件化方法在训练侧有效而未能泛化时，应分别报告“可控性存在”与“可部署修复未成立”。

| 阶段 | 主要工作 | 完成／进入下一阶段的依据 |
| :---: | :--- | :--- |
| A 协议与资产核查 | 核实RL身份、缓存粒度、分组可重算性、原收益矩阵；冻结划分、种子及实际候选清单；统计样本／会话与秩 | 输出来源清单、复用／补算说明及工程冒烟；不重复第一批全局大扫描 |

C与D允许在探索集内交替，但不能把E中的评价结果回流而仍称其为独立确认。不同K、初始化和可独立拟合的专家任务并行调度；有结果的候选可滚动进入后续计算，统一冻结边界清楚记录。

## 12. 专家化结果之后保留的研究

此前讨论的进一步诊断和方法没有被否决。优先完成专家化主线；其中能帮助专家发现的小实验已纳入上文，其余在新结果形成后按以下分支安排：

| 新结果 | 后续重点 |
| :--- | :--- |
| 专家Oracle明显提高，实际路由仍弱 | 判断路由信息是否足够、条件收益是否跨噪声可预测；比较后验轨迹信息与两次前向，检查保守拒绝与风险校准 |
| 逐场景有效，组共享仍弱 | 检验组内冲突、连续条件化和力度是否不足；不立刻无限增加专家数 |
| 受限全维有效，现有质量子空间弱 | 按行为敏感性重选空间、token与路径，检验质量相关方向是否缺少控制能力 |
| 一组噪声有效，换噪声失效 | 研究采样状态兼容性，比较场景固定专家与状态条件干预 |
| 局部修改有效，后续效果消失 | 追踪后续层／去噪步如何抵消，比较单点、持续和联合干预 |
| 多种位置／空间在合理搜索下均弱 | 明确所测干预族和预算边界，再讨论是否降低该方向优先级，不泛化为数学上的不可修复 |

更广的受限逐场景上限需比较现有质量空间、随机同维、受限全维以及少量多位置联合，并同时检查原成功损伤及跨噪声保持。动作头参考注入可检查参考状态与当前采样状态的兼容性；已有部分参考注入结果不等于所有位置和替换方式均已否定。VLM没有同输入的成功／失败参考状态，使用受限内部反事实优化并明确特权性质。

最终若获得可信的开放环净收益，再推进闭环验证；闭环资产、协议和额外资源需要现场核实，不在本次落盘时宣称已安排或已完成。

## 13. 工程、调度与资源约束

- 新代码／配置／运行目录独立，第一批冻结代码和结果只读复用，不直接修改师兄源码。导入共享源码时显式安排缓存、日志、临时文件及字节码写入位置。
- 正式计算前核实当前环境、卡型／卡数、内存、挂载、软件、权重和评分缓存。单卡冒烟后，再对实际参与卡和多节点领取／汇总做冒烟；5–10分钟检查样本覆盖、轨迹、指标与异常，不仅看存活或利用率。
- 节点数、设备列表、全局rank和CPU并发均可配置，验收按实际参与清单，不写死32卡或双节点。CPU统计／拟合与GPU推理／评分用独立细粒度队列衔接，按实测吞吐分配，避免整节点等待。
- 后续新程序做一次短程分段计时：读取／解压、推理、设备回传、评分、写盘。优先评估预取、减少同步和流水重叠；按场景吞吐和总时间决定采用。完全相同轨迹可复用评分；不能默认增加评分进程必然加速。优化用独立版本，验证轨迹、种子、评分等价后采用，不中途修改冻结运行。
- 长任务采用简单监控脚本和工具托管后台终端等待，检测完成或异常后返回，由智能体验收接续；默认约60秒机械轮询，按现场和用户节省额度要求调整，避免高频人工／模型轮询。不得仅放后台后结束而要求用户再次提醒。
- 状态原子写入，领取防重，保存失败rank及原异常，瞬时共享存储错误有界退避。中断后保留种子、分块、claim和未完成清单，只恢复确认中断的任务，不抢占其他在途工作。
- 计算开始时核实实际仍在运行且属于本任务的节点，不把旧状态文件当实时云端证据；优先复用经核实的既有节点。新建DLC按当前[研究AGENTS.md](../AGENTS.md)设置运行上限**72小时／4320分钟**，按用户最新修改的统一约定执行；提交后回读确认。
