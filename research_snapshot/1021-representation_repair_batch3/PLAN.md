## 4. 统一候选库

### 4.1 候选身份与清点

为每个可重放候选建立唯一记录：`candidate_id`、来源任务／配置／拟合种子／训练范围、代码与权重SHA、干预位置与顺序、token范围、子空间与中心化方式、算子、力度规则、实际范数预算、内部条件和所需输入。

覆盖第一批独立算子与第二批可用专家、解析修复、学习型修正、条件化完整策略及实际联合软干预。旧失败门控策略与去门控版本是不同候选：去门控必须在本批独立配置下真实执行。旧“只对失败推理”的结果不能给未计算的成功样本臆造修复输出。

相同实际配置可去重并保留来源别名；共享专家不因多个路由引用而重复推理。不同候选即使轨迹完全相同，可以去重评分，但不能据此断定它们的内部表征也相同。

只有表征统计或未完成模型、无法复现的中间产物不冒充现成专家。清点时区分可直接重放、可用已有资产补齐和缺少必要资产，保留原因；不以原在线路由成绩替代工程可用性判断。

### 4.2 两套候选池

| 池 | 定义 | 必须保留的对照关系 |
| :---: | :--- | :--- |
| A：现有方法池 | Base＋清点后全部合格现有完整修复候选 | 不要求单专家或在线路由独立提分 |
| B：逐场景增强池 | 完整保留 A，再加入逐场景优化产生的实际候选 | B包含A；同一逐采样评价的B择优分数不应低于A |

优先研究VLM／接口，但动作头方法仍能按最高分获选。若后续扩展已有算法的力度／空间等配置，先在训练／验证侧建立独立来源记录，随后统一冻结测试清单。主任务不要求重训新的K系统。

联合软干预作为完整算法执行，保留混合规则及实际下游前向；不将单专家得分、轨迹或表征线性相加当作其效果。使用原有路由的完整策略可入库，同时保留可独立执行的原始分支，离线Oracle最终直接比较真实分数。

### 4.3 宽搜与新增候选：未解决场景预筛后晋级

首版42候选完成后，以当前**已验收**候选集合为参照，只在训练／开发侧构造场景预筛池。令 `M(i,j)=max_c Q(i,j,c)`，预筛池取以下两类场景并集：

```text
U1 = {i: 存在j∈{0,1,2,3,4}，M(i,j)<0.90}
U2 = {i: max_c mean_{j=0..4} Q(i,j,c)<0.90}
U = U1 ∪ U2
```

两类不等价：U1允许每次采用不同候选，U2要求五次固定同一个候选。例：A的五次为`[95,95,95,80,80]`，B为`[80,80,80,95,95]`，逐采样Oracle五次均95，但场景固定Oracle为89；该场景仍需进入U2。若“平均”指逐采样Oracle自身的五次平均，则其低于90确实已被U1覆盖，**本计划U2不是这个定义**。

新候选先在U上使用相同观测、S0～S4配对噪声执行并真实评分，分别计算加入已有集合后的逐采样与场景固定增量。**只要至少一个场景在任一种口径下出现可信、可重复的改善，即可晋级全量。** 不要求候选整体平均超过90，不要求每次采样改善，不设改善场景比例下限，也不设额外安全准入。可信性核查保留未舍入分数、实际轨迹、重复执行／独立重新评分及数值一致性证据；同噪声复现与跨噪声有效性分别标注，不把前者冒充后者。

晋级后补齐全量103,288场景训练／验证的五采样，再按该批预先冻结的候选及评价协议计算完整测试，验收后正式更新三种口径及实时最优清单。全量评价自然覆盖原先90分以上场景，不用预筛子集成绩替代总体成绩。原计划已确定全量评价的成型专家与完整策略直接进入全量流程，不因U上收益弱而取消。

每轮保存预筛池版本、参照库指纹、完整候选搜索范围、实际覆盖、收益及复现证据、晋级／未晋级原因和来源。随着库扩展可重新生成U，但保留旧版本，不覆盖原始结果。测试结果不参与构造U、晋级或补库；首版42教师快照保留，后续只更新实时最优，待用户明确要求再冻结新教师。

**R3信息隔离贯穿预筛、配置筛选和晋级。** 为R3单独用S0～S2构造相应未解决池及晋级证据；可以共享相同候选的实际前向和评分，但S3／S4不能决定其R3配置准入、选择或预算。仅靠五采样口径晋级的新增候选可进入R1／R2库，不能据后两次表现自动回填R3；报告两套准入范围与差异。事先已确定全量评价的成型候选不依赖本轮后两次结果入库。R3锁定后两次评价允许下降，不能反向淘汰或调整。

## 5. 三种口径与六组主结果

设场景为 `i`，采样编号为 `j`，完整候选为 `c`，真实PDMS为 `Q(i,j,c)`，`c=0`表示Base。所有主增益均先在相同评价噪声上相对配对Base计算，再在场景上汇总。

| 口径 | 选择与评价 | 科学含义 |
| :--- | :--- | :--- |
| R1：逐采样Oracle | 每个 `(i,j)` 分别取最高分候选；在S0～S4汇总 | 可针对每次生成事后选择的上限 |
| R2：场景固定Oracle | 为场景选择五次平均PDMS最高的一个完整候选，再评价该固定候选的五次输出 | 同场景固定修复状态／规则的事后上限 |
| R3：跨噪声固定方案 | 仅用S0～S2选择／优化一个完整候选；锁定后评价S3、S4 | 固定修复方案对未参与本次选择与优化的噪声是否有效 |

明确计算：

```text
R1(i) = mean_{j=0..4} max_c Q(i,j,c)
c2(i) = argmax_c mean_{j=0..4} Q(i,j,c)
R2(i) = mean_{j=0..4} Q(i,j,c2(i))
c3(i) = argmax_c mean_{j=0..2} Q(i,j,c)    # 新优化产物也只能使用S0～S2构造
R3(i) = mean_{j=3..4} Q(i,j,c3(i))
```

| 主结果 | 现有方法池 A | 加逐场景优化池 B |
| :--- | :---: | :---: |
| R1：逐采样Oracle | A-R1 | B-R1 |
| R2：场景固定Oracle | A-R2 | B-R2 |
| R3：跨噪声固定方案 | A-R3 | B-R3 |

固定的是完整候选及其执行规则，不是只固定一个算法名字。固定候选内的可观察条件化计算允许按冻结规则执行；不得读取本次真实PDMS决定力度或回退。对逐场景优化，“固定”还必须包含固定优化所得的实际修正参数。

R2、R3不得在每次生成后又用真实PDMS决定是否回退Base；如果另算这种混合口径，必须单独命名，不能替代六组主结果。R1逐输出不低于Base；R2的五次平均不低于Base但单次可能下降；R3的新噪声均值也可能下降。后两者的下降如实报告，不事后筛除。

R1和R2的选择使用了被评价输出的真实结果，两者都是特权上限。R3只检验该固定方案的跨噪声迁移，不将同一场景重复采样当作独立新场景泛化。对同一完整候选矩阵，核验 `R1 >= R2`；不得把不同生成预算的两套矩阵套用此恒等关系。

## 6. 逐场景表征优化

### 6.1 方法

冻结Base，在位置 `L` 的原始表征 `h_i` 上寻找该场景的修正参数 `delta_i`，通过真实后续网络和完整动作去噪链生成轨迹。GT／已评分优质轨迹可提供可微代理目标，真实PDMS用于候选评估与最终选择；不把不可微评分直接当作可反传损失。

优先复用第二批已验证的接口投影前／后受限优化实现，继承原生采样与评分链路；随后在训练／验证侧判断是否扩展位置、子空间、算子、力度及初始化。允许从Base或已有优质分支初始化，但记录完整干预顺序和总体预算。范数／优化步数属于方法配置，不是额外的安全选优条件。

已有实现的24步及相对范数预算0.005／0.02／0.1可作为工程起点，不自动宣称它们是第三批最优或唯一搜索范围。位置、参数化、优化器、步数、重启数、力度范围、真实评分频率和停止规则，经训练／验证预检后写入独立配置并冻结；记录实际搜索次数和未完成范围。

GT允许用于优化辅助与诊断，但主库保存Base／修复后的模型实际生成输出。GT轨迹本身不直接冒充具有对应内部前向状态的模型分支；GT使用情况逐候选标注。

### 6.2 对三种口径的适配

- R1允许按噪声分别优化修正，也可选择已有共享修正，最终逐输出真实评分择优。
- R2需要一个固定修正或固定完整候选。可直接优化五噪声的平均代理目标，也可把某次采样优化出的修正固定后实际重跑全部五噪声，再按平均真实PDMS择优；不能平均多个修正后假定仍然有效。
- R1／R2尽量共享已有实际候选与完整评分矩阵；未经所有必要噪声评分的修正不能当作完整R2候选。
- R3单独维护只使用S0～S2生成和选择的优化产物；初始化选择、早停、重启筛选和预算适配均不能读取S3／S4结果。锁定实际修正后，才执行后两次评价。
- 利用全部五噪声优化的产物不得回填R3，即使其算法名称相同。共享只读Base输入／前向缓存可以复用，带有后两次反馈的优化状态不能复用。

测试中的逐场景GT辅助优化明确标为**测试期特权优化上限**。它是在冻结搜索算法下为测试场景寻找修正，不是学生泛化成绩；其输出仅作诊断，不能进入学生监督或用于回头改搜索方法。

## 7. 教师资产与后续蒸馏接口

所有候选至少保存轨迹、PDMS及全部评分分项、完整执行身份与可复现配置。首版42候选按用户要求保存教师快照及同次前向的下游接口表征。后续阶段维护可追溯的实时最优清单，保存相关配对执行资产，但不自动将每次更新冻结成新教师快照；待用户要求提取时再冻结。优先统一到VLM→动作头接口投影后的实际张量；以实际模型的token定义、掩码与张量形状为准，保留完整有效token，不以用于分析的池化向量代替。

每份教师记录包含：

- 场景token、会话、数据划分、观测／缓存版本、采样编号和实际种子。
- 候选池、R1／R2／R3口径、候选ID、代码／权重／空间指纹及原始方法来源。
- 原始Base输出、获选轨迹、真实PDMS与分项、轨迹指纹及评分协议。
- 同次执行的接口表征、有效token掩码、位置与dtype、表征指纹及执行记录ID。
- 逐场景优化的位置、实际修正参数、预算、初始化、优化随机种子、使用的采样集合、GT辅助标志。
- 相对Base的接口变化，以及该修复是否发生在统一监督接口之后。

动作头候选仍可成为最高分教师，但其VLM接口可能与Base相同。对此保留真实接口并明确标注，不能宣称该接口已经编码了后续动作头修正；后续蒸馏再据此决定监督位置或权重。必要的下游动作表征采集使用独立记录，不伪造统一接口目标。

如果候选评价时尚未保留入选表征，可以按完整执行身份重放，重新同时取得轨迹与表征，核对轨迹和评分一致后接纳该配对；不能只补一个未经重放核对的隐藏状态。相同轨迹的评分去重不丢失不同表征的来源关系。

R1、R2、R3分别导出教师清单。跨噪声一致的上游固定修复通常提供更自然的接口监督；R1保留为更强的逐输出上限与多目标教师方案，不提前抛弃。在线不接收动作噪声的学生接口无法逐次对应不同噪声专属隐藏目标，这一问题留给后续蒸馏消融；本批不通过直接平均隐藏状态来掩盖它。

后续核心对照为同一批教师轨迹、相同训练数据与预算下的轨迹监督和联合监督。教师Oracle不能代替学生新场景成绩，联合蒸馏是否优于仅轨迹监督仍须实际训练验证。
